## Restore protocol

The helper consumes a single JSON plan with absolute or cwd-relative `targetPath`, `backupPath`, `archivePath`, `diagnosticPath`, `expectedOriginalSha256`, and `expectedGeneratedSha256`. Expected hashes are explicit, immutable lowercase SHA256 strings. Example invocation: `node scripts/restore-historical-output.mjs plan.json`. The CLI returns non-zero on failure.

1. Validate distinct paths/regular files; verify original backup and current generated target hashes.
2. Exclusively create and verify generated archive; never overwrite an existing archive.
3. Exclusively write/flush/close a unique original copy in the target directory and verify its hash.
4. Materialize/verify a second same-directory replacement copy; retain the original copy because rename consumes its source.
5. Recheck target hash, perform exactly one `fs.renameSync`, then verify the target, backup and archive hashes.
6. Remove the original temporary copy only after successful verification. A cleanup failure is still FAIL.

No direct write/truncation of the historical target; no deletion fallback, sleep or retry. Any failure leaves all existing target/backup/archive/temporary evidence intact; no automatic rollback or retry is performed. Post-replacement verification failures remain FAIL with the verified temporary original retained. The protocol is deterministic in byte outcomes and order; unique temporary names prevent collision. It does not claim power-loss recovery or exclusion of external concurrent writers. The native filesystem operation must be supported; unsupported replacement fails closed.

Failure telemetry records timestamp, Node version, PID, operation/source/target/parent paths, errno/code/syscall/message/stack, target existence/size/mode/mtime, backup/current hashes, temporary locations and a read-only Windows .NET attributes/open probe. Probe exception HRESULT (decimal/hex/type/message) is explicitly attributed to the probe. Node's translated errno is never invented as a native Windows error code. Diagnostic failures are attached without masking the original error; the CLI still prints the failure and returns 1. No external utilities are installed.

Design references: [Node fs.renameSync](https://nodejs.org/docs/latest-v24.x/api/fs.html#fsrenamesyncoldpath-newpath), [Windows MoveFileExW replacement/error contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw). Documentation establishes API behaviour, not the original UNKNOWN root cause or a universal filesystem guarantee.
